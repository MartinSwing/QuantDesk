# QuantDesk 功能对比分析与规划报告

> 对标产品：腾讯自选股、招商证券（智远一户通）、平安证券、富途牛牛
> 分析基准：QuantDesk 当前功能面（2026-10-18）
> 定位说明：QuantDesk 是毕业设计性质的模拟交易/行情系统，功能规划兼顾**答辩亮点**与**真实产品价值**，不盲目对标持牌券商的全部能力。

---

## 一、项目现状盘点

已实现：用户注册/登录/管理员管理、入金/出金（含渠道备注）、股票买卖（佣金/印花税/一手校验/自定义成交价与时间）、自选股、六大指数卡片+指数K线详情页（缩放、7档时间段）、个股搜索与K线、持仓与资产、资金流水、交易记录、Tushare数据源+本地缓存降级。

**尚未涉及的大域**：盘口/分时、排行榜与市场概览、提醒推送、委托撮合流程（目前直接成交）、绩效分析、资讯数据（龙虎榜/新闻/IPO——旧项目有、新项目未迁移）。

## 三、优先级评估（成本 × 收益）

评估维度：答辩/面试加分、真实产品价值、实现成本（以现架构的人天估算）、数据可得性（Tushare 免费额度）。

**结论先行**：当前系统最大的短板不是"缺炫功能"，而是 **① 交易流程过于简化（无委托环节）、② 缺少"分析自己"的能力（绩效）、③ 行情维度单薄（无排行/分时/盘口）**。优先补这三块。

| 象限 | 功能 |
|------|------|
| 高收益·低成本（先做） | A1 排行榜、B1 价格提醒、C4 净值曲线基准对比、A4 F10基本面、A6/D1/D2 旧功能迁移 |
| 高收益·中成本（重点做） | C1 委托撤单、C3 绩效分析、A2 分时图、C2 条件单 |
| 中收益·中成本（选做） | A5 板块资金流、E1 暗色模式、E3 WebSocket |
| 低收益·高成本（不做/缓做） | E4 多市场、E5 Level-2、E6 社区大赛 |

## 四、实现思路与难点（逐项）

### P0-1 涨跌排行榜（约1人天）
- **思路**：新增 `rank_bp.py`；数据直接查本地 `stock_daily` 表最新交易日的全市场行情（已有1000万条缓存+`trade_date`索引，毫秒级），SQL 按 `pct_chg`/`amount` 排序取 Top50；前端新增"排行榜"页或行情中心 Tab，红涨绿跌表格。
- **难点**：需要 `stock_basic` JOIN 取股票名称与行业；停牌股（当日无成交）要排除；注意与降级逻辑兼容（缓存最新日期≠真实最新交易日）。

### P0-2 价格提醒（约1-2人天）
- **思路**：新表 `price_alerts(id, user_account, stock_code, target_price, direction(above/below), status, triggered_at)`；后端起一个守护线程（或 Flask scheduler）每分钟拉自选股+活跃提醒的最新价比对；触发后写站内消息表，前端导航栏加红点/弹窗轮询 `/api/alerts/pending`。
- **难点**：守护线程与 Flask 多进程/调试模式重载的兼容（用 `before_first_request` 或独立脚本）；避免重复触发（触发后置 `triggered` 状态）；降级模式下用缓存价判断要标注。

### P0-3 账户净值曲线 + 沪深300对比（约1-2人天）
- **思路**：写定时任务或按日快照——每日收盘后把 `总资产` 写入 `account_equity_snapshots(user_account, date, total_asset)`；历史部分可用现有交易流水回放补算；前端 ECharts 双线图：账户净值（归一化）vs 沪深300收盘价（归一化），直接展示超额收益。
- **难点**：历史快照回放的口径（出入金会干扰收益率，需用"复权"思路剔除入金影响——时间加权收益率最严谨，简化可用单位净值法）；快照任务失败重试幂等。

### P0-4 个股详情页 F10（约1人天）
- **思路**：Tushare `daily_basic` 接口（市盈率/市净率/总市值/换手率）+ `stock_basic`（行业/上市日期），缓存到 `stock_daily_basic` 表；在现有 `stock_kline.html` 顶部加一排关键指标卡片。
- **难点**：`daily_basic` 有积分门槛与频率限制，需要本地缓存+降级（沿用现有 tushare_client 冷却机制即可）。

### P0-5 旧项目功能迁移：龙虎榜/新闻流/IPO（约2-3人天）
- **思路**：旧 `Stock_Market` 项目这三个功能代码完整，按新架构拆到 `models/`+`services/`+`api/` 三层，建 `top_list`（龙虎榜）、`news`、`ipo` 三张表；入口放行情中心导航。
- **难点**：旧代码是单文件面条式，迁移时重写 DAO 层；注意 Tushare 接口的积分要求（龙虎榜 `top_list` 需一定积分）。

### P1-1 委托与撤单（限价单）（约3-4人天）⭐ 答辩核心亮点
- **思路**：新表 `orders` 增加 `order_type(limit/market)`、`status(pending/filled/cancelled)`、`frozen_balance` 启用（`accounts` 表字段已预留）；买入挂单冻结可用资金、卖出挂单冻结可卖股份；撮合服务每分钟比对挂单价与最新价（限价单：买价≥现价即成交），成交后走现有 buy/sell 的资金持仓事务；新增"委托列表"页支持撤单（解冻）。
- **难点**：撮合与撤单的并发竞争（对 order 行 `FOR UPDATE`）；部分成交可先不支持（简化为全量成交）；冻结资金的可用资金计算要贯穿 deposit/withdraw/buy 全链路，容易漏。

### P1-2 绩效分析页（约2-3人天）⭐ 数据科学专业加分项
- **思路**：基于交易记录+净值快照计算：累计收益率、年化收益、最大回撤、夏普比率、胜率（盈利单占比）、盈亏比、平均持仓天数；后端纯 pandas 计算，前端 ECharts 展示+指标卡片。
- **难点**：年化/夏普需要日频净值序列（依赖 P0-3 的快照表）；模拟数据时间跨度短时年化指标会失真，页面加说明。

### P1-3 分时图（约2人天）
- **思路**：Tushare 分钟接口（`stk_mins` 需积分较高，免费替代：用 `rt_k` 实时接口或自建盘中轮询落库）；分时图 = 1分钟线 + 均价线 + 昨收基准线，ECharts 渲染；若数据源不可行，降级方案为"最近N日多日分时"用5分钟线。
- **难点**：**数据源是最大风险**——免费 tushare 账户分钟级数据权限有限，先验证权限再动工；盘中轮询的频率控制（防止限流）。

### P1-4 条件单（止损止盈）（约2-3人天）
- **思路**：在 P1-1 委托体系上扩展：`orders` 加触发条件字段（`trigger_price`、`condition`）；撮合服务先判条件是否触发，触发后转限价单成交；前端"条件单"Tab，创建时选持仓股一键带出。
- **难点**：依赖 P1-1 的撮合框架；边界情况多（触发即涨停无法成交、当日有效 vs 长期有效）；答辩演示时要准备好触发脚本。

### P2-1 板块/行业资金流（约2人天）
- **思路**：Tushare `moneyflow`（个股资金流）+ `stock_basic.industry` 聚合成行业级；热力图用 ECharts treemap。
- **难点**：`moneyflow` 接口积分门槛较高；行业聚合口径（申万一级 vs tushare 自带行业）。

### P2-2 暗色模式（约1人天）
- **思路**：`style.css` 颜色全部抽成 CSS 变量，`body.dark` 类切换；图表主题用 ECharts `dark` 主题注册；导航栏加切换按钮，偏好存 localStorage。
- **难点**：K线红绿配色在深浅主题下都要符合A股习惯（涨红跌绿不能反）。

### P2-3 WebSocket 行情推送（约2-3人天）
- **思路**：Flask-Sock/SimpleWebSocket，自选股页建立 WS 连接，服务端每 N 秒推送最新价；轮询接口保留作为降级。
- **难点**：数据源仍是轮询 Tushare 得来的，WS 只是传输层优化，别过度包装成"实时行情"；多连接的广播效率。

### 不建议做
- **Level-2 十档/逐笔**：需付费数据权限，模拟系统收益低。
- **多市场（港美股）**：tushare 港股接口积分要求高，且汇率/交易规则（如港股一手股数不固定）会显著增加交易模块复杂度。
- **社区/模拟大赛**：工程量大、偏离毕设主题。

## 五、按优先级排序的功能规划清单

### 第一期：补齐核心体验（约1.5-2周，答辩前建议完成 P0 全部 + P1-1）

| 优先级 | 功能 | 预估成本 | 收益 |
|---|---|---|---|
| **P0-1** | 涨跌排行榜（涨幅/跌幅/成交额榜） | 1人天 | 行情中心从"只有6个指数"变成完整市场概览；纯本地缓存实现，零数据风险 |
| **P0-2** | 自选股价格提醒 | 1-2人天 | 自选股模块价值质变；演示效果好（现场触发） |
| **P0-3** | 账户净值曲线 vs 沪深300 | 1-2人天 | 回答"跑没跑赢大盘"；为绩效分析打地基 |
| **P0-4** | 个股 F10 基本面指标 | 1人天 | 个股页信息完整度大幅提升，成本低 |
| **P0-5** | 迁移龙虎榜/新闻流/IPO | 2-3人天 | 旧资产复用，功能密度快速提升 |
| **P1-1** | 委托/撤单（限价单撮合） | 3-4人天 | **补上交易系统最大短板**，从"模拟下注"升级为"仿真交易系统"，答辩核心竞争力 |

### 第二期：量化特色深化（P0 完成后）

| 优先级 | 功能 | 预估成本 | 收益 |
|---|---|---|---|
| **P1-2** | 绩效分析（收益/回撤/夏普/胜率） | 2-3人天 | 数据科学专业人设的最强佐证，面试可深聊 |
| **P1-3** | 分时图 | 2人天 | 看盘基本盘（先验证数据权限） |
| **P1-4** | 条件单（止损止盈） | 2-3人天 | "Quant"定位的点睛之笔，依赖 P1-1 |

### 第三期：体验优化（有余力再做）

| 优先级 | 功能 | 预估成本 | 收益 |
|---|---|---|---|
| **P2-1** | 板块/行业资金流热力图 | 2人天 | 富途式亮点（验证积分后） |
| **P2-2** | 暗色模式 | 1人天 | 看盘标配，改动纯前端 |
| **P2-3** | WebSocket 推送 | 2-3人天 | 演示动效加分 |

### 明确不做
Level-2 十档、多市场（港美股）、社区与模拟大赛 —— 数据成本或工程量与毕设收益不匹配。

## 六、一条主线建议

如果只做一件事，做 **P1-1 委托撮合**；如果有时间做两件，加 **P1-2 绩效分析**。理由：前者让系统从"能玩"变成"像真的"（交易系统的本质），后者让"QuantDesk"的 Quant 名副其实——两者叠加，答辩故事线就是完整的一句话：

> "我按真实券商的交易链路实现了资金-委托-撮合-持仓的闭环，并用量化方法对交易绩效做了归因分析。"
